# Type Pairer · 离线合并台

排版团队各自离线调字体配对，合并时不再互相覆盖字号/字距。

## 工作流（离线续作）

1. **导出我的改动包**：得到一个 JSON，内含「三方合并基线 + 我的当前状态 + 合集」，可经任意方式转发、多跳传递。
2. 同事**离线继续调**，随时再导出 ta 的包。
3. 回到本机点**导入同事改动包**：本地按字段做三方合并。
   - 只有一边改了字段 → 自动并入；
   - 两边都改且结果不同 → **两版都保留**，工作值暂取本机版，在配对页挂「待解决冲突」卡，注明双方作者与修改时间，可采用本机版 / 对端版 / 另给一版；
   - 同一个包不会被并入两次（`processedBundles` 去重）。
4. 冲突解决、发布确认都可以继续导出，离线链路不会断。

## 关键规则

- **修订号 `revision`**：每改一个被追踪字段（含字体、字号、字重、行高、字距、文案、分类、合集归属）+1；收藏不升号。
- **发布失效**：标题或正文字体一变，旧发布快照保留但状态变为「待重新确认」（页面卡片、工作区状态条、导出 CSS 头部都会标明，含旧版本号与旧字体）。字体字段存在未解决冲突时无法确认发布。
- **原子提交**：所有保存都是「暂存键 → 正式键 → 清暂存」；提交失败自动回滚正式键并清暂存，**不留半批数据**，重试安全。启动时若发现残留暂存，一律视为失败现场丢弃，正式数据不动。
- **单合集归属**：`collectionId` 为单值（一个 id 或 null），归属变更同样参与三方合并。
- **旧数据升级**：旧 `type-pairs` 键（无修订号）首次启动自动迁移——全部补 `r1`、收藏原样保留、为旧分类补建同名合集、发布状态置为待确认，迁移写入与正常保存同一原子路径。

## 文件结构

- `src/core/types.ts` — 数据模型（修订号、冲突、发布快照、离线包）
- `src/core/engine.ts` — 字段修订、三方合并、冲突保留/传播/收敛、发布状态（纯函数）
- `src/core/persistence.ts` — 原子提交、旧数据迁移、离线包解析、CSS 导出（含待确认/冲突来源）
- `src/core/useWorkspace.ts` — React 状态层（先计算后提交，失败不动内存状态）
- `src/components/ConflictPanel.tsx` — 冲突两版卡片
- `selftest/run.ts` — 核心逻辑自测（17 项）
- `selftest/ui.smoke.test.tsx` — jsdom 真实 UI 冒烟（6 项）

## 验证

```bash
npm install
npm test        # 17 项核心 + 6 项 UI，全部通过
npm run build   # 类型检查 + 生产构建
npm run dev     # 本地试用
```
